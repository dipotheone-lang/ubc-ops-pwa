# UBC Solver — محسّن المشتريات والتوريدات

أول محرك قرار لنظام United Brothers Ops: **ترسية طلبات الخامات على الموردين**.
بياخد طلبات الشراء (MR lines) وعروض الموردين، ويطلع أوامر شراء مقترحة بأقل **تكلفة فعلية**.

## بيحسب إيه؟
تكلفة فعلية = السعر (مع شرائح الكميات) + النقل + علاوة مخاطر الموردين (حسب التقييم)
− ميزة شروط الدفع الآجل + غرامة التأخير عن تاريخ احتياج الموقع (بوزن الأولوية) + تكلفة ثابتة لكل أمر شراء.

## قيود صارمة
- موردين معتمدين فقط (`Approved`، و`Conditional` بخيار) والعروض سارية
- الحد الأدنى للكمية (MOQ) وطاقة المورد **المشتركة** بين كل الطلبات والمشاريع
- أقصى عدد موردين لكل MR، وأدنى قيمة أمر لكل مورد
- ميزانية المشروع (مرنة: تتخطاها وتنبّه بدل ما توقف الشراء)
- لو مفيش عرض مناسب: النقص بيظهر في `unmet` بدل ما الحل يفشل

## التشغيل
```bash
pip install -r requirements.txt
python -m pytest -q                                   # 16 اختبار
python -m ubc_solver.cli demo --solve                 # بيانات تجريبية
python -m ubc_solver.cli solve my_input.json -o out.json
```

صيغة الإدخال: `examples/demo_input.json` (`suppliers`, `requirements`, `offers`, `budgets`, `params`).
الإخراج: `awards`, `draft_pos` (جاهزة للتحويل لـ PurchaseOrders/POLines بنفس أسماء حقول v2), `unmet`, `warnings`, `summary`.

## ملاحظات مهمة
- **بيانات الديمو تخيلية** (أسعار تقريبية للتوضيح، مش عروض حقيقية).
- `lower_bound_spend` حد أدنى نظري (أرخص سعر بدون قيود)، مش خط مقارنة واقعي. التوفير الحقيقي بيتقاس مقابل
  ما كان بيتشترى فعلاً (PO تاريخية) — محتاج بيانات الشركة.
- النظام الحالي مفيهوش جدول **عروض الأسعار (Quotations)**؛ لازم يتضاف (سطر لكل مورد × صنف: شرائح سعر، MOQ، طاقة،
  مدة توريد، أيام سداد، صلاحية) عشان الـ solver ياخد مدخلاته من الشيتات.
